## The programme

The [MSc/MPhil in Intelligent Computing Systems](https://ashesi.edu.gh/masters-in-intelligent-computing-systems/) is a two-year graduate programme at Ashesi University, Berekuso, Ghana. It trains computer science professionals to employ data science and artificial intelligence in engineering secure real-world systems, and it sits on three concentration areas:

| Concentration | Courses in the catalogue |
| --- | --- |
| **Software Engineering & Systems** | Software Engineering Essentials · Agile Methods · Software Measurement & Testing · Cloud Computing · Embedded Systems · Blockchain · Internet of Things |
| **Artificial Intelligence & Data Science** | Machine Learning & Data Science · Deep Learning · Natural Language Processing · Computer Vision · Autonomous Robotics |
| **Cybersecurity** | Cybersecurity Essentials · Security Architecture & Software Security · Security Management · Privacy-Preserving Systems · Cloud & IoT Security · AI & Security |

Everyone takes at least two courses from each concentration and goes deeper in one, then finishes with *Building Secure Intelligent Systems* (a team project course) and either an industry practicum (MSc) or a thesis (MPhil).

## What we do

Most of our courses run on **Prosits** (problem situations): Ashesi's problem-based learning format. Each Prosit is a multi-week brief set in a real Ghanaian or African context, worked on in a team of four to six, with a repo, a written report and a debrief or defence at the end. Everything below is Fall 2026.

| Code | Course | Teams | What we have built so far |
| --- | --- | :---: | --- |
| **ICS 530** | Software Engineering Essentials | 2 companies | Each "company" picks a product, writes a proposal, builds it with Scrum from 9 Nov to 18 Dec 2026 and presents at **ASERC** with a paper, slides and a live demo. [Nyansapo](https://github.com/ASU-MICS-2028/se-company-a-capstone) is building **Twɛn**, a virtual queue for outpatient clinics joinable by USSD, SMS or web; [Nkenten](https://github.com/ASU-MICS-2028/se-company-b-capstone) is Company B. |
| **ICS 534** | Cloud Computing | 3 teams | **Prosit 1 · AgroConnect:** offline-first farmer registration and extension services for rural Ghana. **Prosit 2 · HealthConnect Ghana:** offline-first health records, visits and referrals for community health workers, synced to an AWS event-driven backend. **Prosit 3 · SmartCity Accra:** IoT sensors, time-series storage, forecasting and alerting for the Accra Metropolitan Assembly. Terraform, auto-scaling, monitoring and cost control throughout. |
| **ICS 553** | Machine Learning Essentials | 4 groups | **Prosit 1:** where should Ghana's limited insecticide-treated bed nets go? DHS survey weighting, leakage-audited pipelines and district-level priority rankings. **Prosit 2 · NkwaPay:** responsible credit scoring for a mobile-money lender, trained on Kenyan loans, tested for transfer to Ghana, audited for fairness and regulation, shipped as a scoring service with plain-language reasons. **Capstone:** each group's own problem, e.g. weekly flood early warning for Ghana's 16 regions and next-day unhealthy-air warnings for Accra. |
| **ICS 554** | Natural Language Processing | 3 groups | **Prosit 1:** language models from scratch for **Ewe**, a low-resource Ghanaian language (n-gram with smoothing vs LSTM and transformer), plus adapting an open LLM to health and agriculture with LoRA. **Prosit 2:** a platform where a non-developer describes a backend in plain words and a team of LLM agents turns it into a running, tested API. **Prosit 3:** in progress. |
| **ICS 570** | Cybersecurity Essentials | 4 groups | **Lab 2:** a secure student-records portal with passkey (WebAuthn/FIDO2) sign-in, per-request server-side role and ownership checks, and an AES-256-GCM demo, with an evidence report of attack attempts and defences. |

The common thread: offline-first and low-connectivity design, low-resource languages, fairness and regulation, and infrastructure we can actually afford to run. We build for Ghana first.

## How we work

- **Every task is a GitHub issue**, and most teams keep a plan per issue, a file per decision and a file per change (what changed, who was in charge, and how AI assistants were used).
- **Pull requests, not pushes to main.** Review rotates within a team so nobody rewrites another member's work unasked.
- **AI use is declared.** Each repo says which assistants were used and for what, in line with course policy.
- **Public by default, careful by default.** No secrets, no real personal data, no course handouts in the repos.
- **Ghana first.** Problems, data and users are local; the engineering has to work on a feature phone, a 2G connection and a small budget.
